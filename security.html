🎧 EarDeck Threat Model

EarDeck is my free, open source AirPods tray app for Windows, built in Rust. Any Bluetooth device in range can broadcast anything and pick any name, so the main threat is someone nearby. Pick a side of the attack surface to see what could go wrong there and what stops it.

🛡️EarDeck

Malformed Bluetooth packets

Written in Rust, packets must match an exact size and format, and the parser is tested against 200,000 random packets.

A fake device that tries to pair

Pairing only happens when you pick a device. Only AirPods and Beats names are accepted, and EarDeck refuses any device that asks for a PIN.

Fake broadcasts that change the display or pause your media

Broadcasts must match your model and be close by. Auto-pause only runs while your AirPods are connected and are the current output.

A device name built to run code in the popup

Names are escaped, and the content security policy blocks inline and remote scripts.

The popup being sent to a website

Navigation is blocked, and the popup can only load the pages built into the app.

A compromised popup reaching more of the app

It gets only the permissions it needs, and the backend checks inputs itself.

A planted program at startup

The Open at Login path is quoted, which stops unquoted path attacks.

Remote debugging through an environment variable

Cleared when the app starts.

A hand-edited settings file

Values are range checked when loaded.

A vulnerable dependency

cargo audit runs on every change and weekly, and Dependabot proposes updates.

Known Limits

A threat model that claims to stop everything isn't telling the truth, so these are written down too.

  • Fake broadcasts can't be fully stopped, because AirPods broadcasts are not authenticated. Someone nearby could show false battery levels or trigger a pause, but they can't reach your files or your audio.
  • Pairing relies on the device's name, so only pick a device you just put in pairing mode.
  • Releases aren't code signed yet, so the releases page lists a SHA-256 value to check your download against.
  • Malware already running as your user is out of scope, since it could already change anything EarDeck can.

🔒 This Site Defends Itself

A security engineer's website should practice what it preaches. GitHub Pages doesn't let me set response headers, so every defense here has to work from the page itself. For example, the Content Security Policy lives in a meta tag at the top of each page.

🧱 Content Security Policy

Every page starts from default-src 'none' and only allows what it needs.

🚫 No Inline Code

All scripts and styles ship as files, so the policy never needs 'unsafe-inline'.

📦 No Third-Party Scripts

Even the font is self-hosted, so no outside stylesheet or script can change under me.

🔐 HTTPS Everywhere

GitHub enforces HTTPS, and every .dev domain is on the browser HSTS preload list.

📬 security.txt

A standard RFC 9116 file tells researchers how to reach me.

🔬 Static Analysis

CodeQL checks the site's JavaScript on every change and weekly.

🕷️ Dynamic Analysis

A ZAP baseline scan runs against a local copy of the site on every change and weekly.

📌 Pinned Actions

GitHub Actions are pinned to exact commits, and Dependabot proposes updates.

⚠️ Known Gap

Clickjacking protection and violation reports need real headers, which GitHub Pages can't send.

🧪 Live Test

Press the button and this page will attack itself four ways. The results come from your own browser as it runs them, so nothing here is canned.
